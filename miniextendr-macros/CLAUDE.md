# miniextendr-macros

Proc-macro crate — `#[miniextendr]`, `#[miniextendr_init]`, derives (`ExternalPtr`, `Altrep*`, `DataFrameRow`, `MatchArg*`, `Factor`, `Vctrs`, `List`, `TypedExternal`). See root `CLAUDE.md` for project rules.

## Scope
- Compile-time item codegen lives here. Registration aggregation and the
  host-side wrapper/wasm file writers live in `miniextendr-api::registry`;
  `miniextendr-engine` is only for standalone R embedding.
- Shared parser layer (formerly `miniextendr-macros-core`) is now in-crate and re-consumed by `miniextendr-lint` directly.

## Layout
- `lib.rs` — proc-macro entrypoints + the `MiniextendrFnAttrs` / `ImplAttrs` / `ParsedImpl` destructuring. **Add a field here → update all 6 class generators.**
- `naming.rs` — canonical name derivations (R wrapper names, `__miniextendr_*` mangling, class symbols). Single source of truth. All macro-emitted `#[no_mangle]` C symbols are crate-prefixed here (`C_<crate>_<fn>`, `C_<crate>_<Type>__<method>`, `__VTABLE_<CRATE>_…`, `__vtshim_<crate>_…`, `__mx_altrep_reg_<crate>_…`) for webR cross-package uniqueness (#1273) — never reconstruct these shapes inline; call the helpers.
- `type_inspect.rs` — shared type helpers incl. the visibility-marker peel (`peel_visibility_marker`, `peel_return_visibility`, `resolve_visibility` = marker > `invisible`/`visible` attr > shape default, `visibility_marker_error` for nested / argument-position markers, #1213). Bare fns peel in `lib.rs`; `ParsedMethod` / `TraitMethod` peel at parse time (`visibility_marker` / `invisible` fields) so every return-shape predicate sees the inner type; `MethodReturnBuilder::with_invisible` and `r_wrappers::finish_instance_body` apply the decision. Also `call_marker` (#1566): detects a bare `Call` / `CallerCall` parameter type (the condition-call markers, `MAIN_THREAD_BOUND`). `lib.rs` strips the marker from the R-facing inputs, binds it from `__miniextendr_call` at the Rust call site and resolves the attribution via `CallAttribution::resolve` (marker > `call = wrapper|caller` attr > crate default > `wrapper`; always the call as written); a standalone wrapper resolving to `caller` gets a trailing `.call = NULL` formal (`CallAttribution::formal`, S3 methods excluded, #1613) so a hand-written helper can pass on the frame to report; `RustConversionBuilder` emits a `compile_error!` for a marker in any method context.
- `crate_config.rs` — the only manifest read at expansion time: `[package.metadata.miniextendr]` in the user crate's `Cargo.toml` (via `CARGO_MANIFEST_DIR`, cached per manifest dir). Six keys: `noexport_postfix`, the crate-wide default suffix for `noexport` / `internal` free functions (#1454); `source_tags`, the opt-in for `@source` provenance lines on every generated roxygen block (off by default, #1552; every emitter goes through `roxygen::source_tag`); `call_attribution = "wrapper" | "caller"`, the crate-wide default condition-call attribution for standalone fns (#1566; `"caller"` applies to `noexport` / `internal` only); `conversion_error_class = "..." | [...]`, classes appended to every argument-conversion condition after the error type's own `RConditionError` classes (read by `RustConversionBuilder::new` and the sidecar setters via `conversion_error_class()`, and by `miniextendr_init!`, which registers them in `MX_CONVERSION_ERROR_CLASS` for the wrappers preamble's `.miniextendr_conversion_error_class`, so the R-side checks raise them too, #1591); `preconditions = true | false`, the crate default of the type-derived R-side checks (`preconditions_default()`, below every item-level spelling, above the `no-preconditions-default` feature, #1566); and `roxygen_prose_links = "strip" | "keep"`, whether leading doc-comment prose keeps its `[...]` links on its way to `@description` (`roxygen::ProseLinks`, read once in `roxygen_tags_from_attrs_impl` via `roxygen_prose_links()`; default `strip`, because rustdoc and roxygen2 share the syntax and `[name()]` is a valid intra-doc link, so a heuristic can't tell them apart; only a target no R package can resolve, a `crate` / `self` / `Self` root or a `pkg::` part that is not a valid R package name (`roxygen::is_rustdoc_only_target`), loses its brackets under both settings and in non-code tag text, #1739; rustdoc's inline `[text](crate::x)` keeps only its text there too when its destination is any Rust path with a `::`, optionally behind a rustdoc disambiguator (`fn@`, ...), whatever its root, `roxygen::inline_rustdoc_destination`, #1744, #1756, while every URL and a bare `[text](Foo)` stay; a bracketed `` [`Type::method`] `` that names no declared R package is MXL204 in `miniextendr-lint`, #1742; a block that renders no page loses every link in its prose and non-code tag text whatever the setting, #1818: the reader sees the block's own `@noRd`, and a caller passes `roxygen::RdPage::Suppressed` when its attributes take the page away, `lib.rs` for `noexport`, `ParsedImpl::parse` for a class under a plain `noexport` (`ClassDocBuilder::build`'s gate) and its methods, `generate_vtable_static` for a trait impl and its methods; MXL204 skips the same blocks). Line-based scanner on purpose (no TOML dependency in a proc-macro crate); add keys there, not ad hoc. Its `normalize_key` / `parse_string_value` are mirrored in `miniextendr-lint/src/crate_root.rs` (the lint's `[lib] path` reader, #1745); keep both in sync.
- `miniextendr_fn.rs` — `#[miniextendr]` on bare fns. Tagged-condition transport is the only mode; `unwrap_in_r` is orthogonal.
- `miniextendr_impl.rs` (+ `miniextendr_impl/`) — inherent impl methods. Same transport. Class-system dispatch (R6/S3/S4/S7/Env/Vctrs).
- `miniextendr_impl_trait.rs` (+ `miniextendr_impl_trait/`) — trait-impl method codegen, ABI-compatible.
- `miniextendr_trait.rs` — `#[miniextendr_trait]` declaration codegen. Trait-ABI vtable shims wrap in `with_r_unwind_protect_shim` (returns a tagged error SEXP that the View method re-panics into the consumer's outer `with_r_unwind_protect` guard) — see `miniextendr_trait.rs:808`.
- `c_wrapper_builder.rs` (+ dir) — `CWrapperContext` for impl method C wrappers. **Prepends `__miniextendr_call: SEXP` as first param.** The worker wrapper runs the body under `condition::catch_condition` on the worker and turns a caught `RCondition` into its tagged value on the main thread (`error_value::rust_condition_value`), so immediate conditions keep their kind, classes, data and call choice there.
- `externalptr_derive.rs` — hand-rolls C wrappers for sidecar `*_get_field` / `*_set_field` accessors: `(x: SEXP)` / `(x, value: SEXP)`, `numArgs = 1/2`, **no call slot**. Adding a `.call` argument to the R side breaks at runtime (PR #344 reverted this).
- `r_wrapper_builder.rs` (+ dir) — R-side `.Call(C_…, .call = sys.call(), …)` emission (the call as written). `DotCallBuilder` at ~L390 is the canonical site; use `.null_call_attribution()` for lambda contexts (R6 finalizer/deep_clone, S7 getter/setter/validator).
- `r_class_formatter.rs` — shared `MethodContext` for all 6 class generators.
- `return_type_analysis.rs` — return-type → codegen for standalone fns (strict-aware).
- `method_return_builder.rs` (+ dir) — same for impl methods.
- `rust_conversion_builder.rs` (+ dir) — TryFromSexp glue for argument conversion. Every binding is a typed `let` (borrowed slices / `&str` with lifetimes erased via `type_inspect::erase_lifetimes`), because the shared `Err` arm (`conversion_err_arm`) probes the error type by method call (`__mx_conversion_err_parts!(e, expected_known)`: `RConditionError` class/message/data, the R-worded reason of a built-in `SexpError`, else `Display`) and `conversion_condition_value` adds the R-terms prefix from `ArgContext` (`'<p>' must be <expected>` via `r_preconditions::conversion_expectation`, else `invalid '<p>' argument`), the crate class, `e$param` and `e$rust_type` (`type_inspect::type_display`) (#1591). Where the prefix is not a literal, the arm also passes `__mx_conversion_arg_message!(e, <name>)`: a `match_arg` choice error then replaces `<prefix>: <reason>` with the R-side `match_arg` check's own message (#1767). A type it has no wording for, in the plain `TryFromSexp` arm only (`ArgContext::with_declared`; other paths may name a type without the impl), is asked on the failure path (`declared_expectation`): `TryFromSexp::__MX_EXPECTATION` (hidden const, set by the newtype derive from its inner type's `conversion_expectation`, else forwarded), or for an `Either` side by side via `from_r::either_expectation` (`expected_arm`: the macro's text, else the side's const, else its own error's expectation, else its `r_value_noun` when another side is named). A `no_na` parameter (`with_no_na`, keyed by Rust name) converted by the plain `TryFromSexp` arm also gets a post-conversion check in the owned vector (`no_na_value_stmt`): `TryFromSexp::__mx_has_na(&x)` (a hidden provided method, `false` by default, overridden by the reading markers and forwarded by `Option` / `Missing` / maps / the newtype derive) → `arg_check_condition_value` with the R guard's message (`r_preconditions::no_na_message`), class and `e$param`, no `e$rust_type` (#1611). No name gate: emitted for every such param, so aliases and derived newtypes are covered. An `Either` param (also under `Missing` or `Option`, `r_preconditions::no_na_checked_after_conversion`; a plain `Option<Either<..>>` converts through its own `TryFromSexp` impl, `NULL` → `None`, while a choice `Either` under `Option` keeps the guard) has no R guard: its input SEXP is bound first (`__no_na_input_<p>`, the conversion binding may shadow it) and the check is `TryFromSexp::__mx_input_has_na(&x, input)`, which by default runs `anyNA()`'s check on the input in Rust (`from_r::any_na`) then `__mx_has_na`; `Either` dispatches it to the arm taken, `Missing` / `Result<T, ()>` / `Option<Either<..>>` / `Option<DataFrame>` / the newtype derive forward it (a `NULL` `None` passes), and `DataFrame` refuses nothing. Detection is by the type as written: an alias, newtype or `Result` around the whole `Either` keeps the guard.
- `dataframe_derive.rs` (+ dir) — `#[derive(DataFrameRow)]`; supports nested enums/structs, HashMap/BTreeMap (parallel `_keys`/`_values` via `unzip`), `as_factor`/`as_list` attrs.
- `condition_derive.rs` — `#[derive(RConditionError)]`: class vector (`#[condition(class)]` on type/variant, snake_case defaults, variant = `<family>_<variant>`), message (`#[condition(message = "fmt")]` else `Display`), `data` from fields (`rename`/`skip`/`debug`; tuple fields need `rename`/`skip`; `message`/`call`/`kind` rejected). `#[condition(call = none)]` on the type or a variant generates `fn call()` returning `ConditionCall::None` there (no call, #1725; `none` is the only value). `#[condition(argument_message = "fmt")]` on a struct or variant (not the enum itself) generates `fn argument_message()`, `Some(format!(..))` there and `None` elsewhere: the whole message of an argument-conversion error (#1833). Generated code drives `defer_*` and `Result` Err arms (#1448).
- `match_arg_derive.rs` + `match_arg_keys.rs` — match.arg codegen; placeholder→choices written at link time via `MX_MATCH_ARG_CHOICES`. A choice parameter's formal default comes only from `ParamAttrs::choice_formal` (`miniextendr_fn.rs`; callers: `lib.rs` for free fns, `r_class_formatter::effective_r_defaults` for inherent and trait methods): the choice vector, `NULL` for `Option<T>`, `None` (a bare formal) under `no_default` / `no_default(p)` (#1828). The prelude always spells the list out, so a `match_arg` placeholder may live in the prelude only and its `MX_MATCH_ARG_CHOICES` entry is still emitted; `choice_doc_suffix` drops the omission note under `no_default`.
- `r_preconditions.rs` — R-side preconditions emitted into wrapper bodies: one `if (!isTRUE(<check>)) .miniextendr_arg_error("<p>", "<requirement>"[, .mx_call])` guard per check (`PreconditionOutput::guards`), raising the same condition as a failed conversion (#1591). An `inherits` / `not_inherits` / `no_na` check with the author's `message` emits `.miniextendr_arg_error("<p>", message = "<msg>"[, call = .mx_call])` (named: after a named `message` a positional call would bind to `what`); `r_string_escape` escapes it (control characters, non-ASCII as `\u{..}`). The `message = ` spellings are parsed in `miniextendr_fn.rs` (`parse_per_param_attr`, and `parse_method_no_na` / `parse_method_class_check`, shared by the impl and trait method parsers; `ClassCheck` says whether a spelling is `inherits` or `not_inherits`, which share every spelling). `not_inherits` (`!inherits(p, c(...))`, #1815) is emitted after `inherits` and before the type checks, because `is.numeric()` is `FALSE` for the classes it usually refuses (`difftime`, `Date`, `POSIXt`); unlike the `inherits` message, its message does not replace the type checks' messages. `inherits(...)` also takes `when(class = ..., message = ...)` hints (#1824; `ExplicitChecks::inherits_hints`, `InheritsHint`; parsed by `parse_when_list` / `parse_method_when`, which spell classes as their check does, `message` required, an error under `not_inherits`): each is one more guard ahead of the `inherits` guard, in written order, `inherits(p, <required>) || !inherits(p, <hint classes>)` with the hint's message, so it fires only for a value that fails `inherits`; `merge` concatenates them. `ExplicitChecks::class_conflict` (a class in both lists, or an `inherits` class in a hint) is checked once a parameter's attributes are merged: in `validate_per_param_attr_conflicts` and `finalize_method_param_attrs`. `conversion_expectation` gives the conversion arms the same type vocabulary. `no_na_requirement` / `no_na_message` word a `no_na` failure for both the R guard and the C wrapper's post-conversion check (`rust_conversion_builder.rs`, #1611). `no_na_checked_after_conversion` drops the `no_na` guard for a non-choice `Either` param (the C wrapper checks it instead); a `match_arg` / `choices` `Either` keeps it (`value_assertions`' `choice` flag, from `skip_params`). Which parameters keep their type-derived checks is `resolve_type_checks` (#1566): the parameter (`Checked<T>` / `Unchecked<T>`, peeled once by `type_inspect::peel_param_markers` in `MiniextendrFunctionParsed::parse` / `ParsedMethod::from_impl_item`, so `inputs()` / `sig` hold the inner type and `RustConversionBuilder::with_param_markers` rebinds it with `from_inner`; the per-parameter keyword; a method's list form) > fn / method > impl > crate `preconditions` > `no-preconditions-default` > on, resolved at codegen into `PreconditionOptions::unchecked`.
- `roxygen.rs` (+ dir) — doc-comment forwarding; class-system doc builders consume this.
- `typed_external_macro.rs` — `TYPE_NAME_CSTR` / `TYPE_ID_CSTR` for R-visible type tags (display + errors).
- `misplaced_dots.rs` — token-level detector for a Rust `...` parameter that is not last (`fn f(x: ..., y: T)` parses as no fn / impl / trait), used by `struct_enum_dispatch`'s fallback to name the `x: &Dots` spelling instead of the struct/enum message (#1737). Mirrored in `miniextendr-lint/src/misplaced_dots.rs`.
- `tests.rs` — UI tests in `tests/ui/*.stderr` snapshots; update when error messages change.

## Gotchas specific to this crate
- **Native-borrow metadata follows the selected converter.** `Call`/`CallerCall` do not convert from SEXP; omit their metadata query so method rejection keeps its intended diagnostic. `CoercionMapping::Numeric` delegates to `TryFromSexp`, so preserve its `NATIVE_BORROW`; only coercion helpers that bypass that trait omit the query. Keep minimal-feature UI coverage alongside full-feature Clippy.
- **Two C-wrapper codegen paths with different signatures.** `c_wrapper_builder.rs` prepends `__miniextendr_call: SEXP` for all `#[miniextendr]` fns/methods; `externalptr_derive.rs` does NOT for sidecar accessors. Don't unify R-side emission without unifying C-side first (#348).
- **`#[miniextendr]` on 1-field structs is removed.** Use ALTREP derives instead.
- **Lifetime params ARE allowed on `#[miniextendr]`.** Lifetimes are erased at codegen — `#[no_mangle] extern "C-unwind" fn f<'a>(...)` produces a single monomorphic symbol and is FFI-safe. Only type/const generic params are rejected (they require monomorphization → multiple symbols → incompatible with `#[no_mangle]`). Borrowed fields on `#[derive(DataFrameRow)]` structs also work (`Vec<Option<&str>>` / `Vec<Option<&[T]>>` companion columns since PR #465).
- **`impl Trait` argument position fails** (E0283 — `TryFromSexp + Trait` across `let` bindings). Return position works.
- **When changing helpers from `TokenStream` → `Result<TokenStream>`, update every caller with `?`.** Otherwise you'll see confusing `ToTokens` bound errors on `Result`.
- **UI test `.stderr` files** must be regenerated when error wording changes (`TRYBUILD=overwrite cargo test -p miniextendr-macros`). **Never overwrite under a `rust-src`-equipped toolchain** — it bakes stdlib spans into the snapshot that CI's minimal stable never renders (#1239). Run the suite via `just test-ui` (auto-isolates under a minimal-profile toolchain) and see root CLAUDE.md "UI test snapshots".
- **MXL111** — `s4_*` method name on `#[miniextendr(s4)]` impl gets `s4_s4_*`. Drop the prefix.
- **S7 fast-path shortcuts** — every non-fallback S7 instance method (inherent *and* trait impl) emits a `<ClassName>_<method>(self, ...)` function that bypasses `S7::S7_dispatch()`. Opt out per-method with `#[miniextendr(s7(no_shortcut))]`. Shortcut names share a namespace with static-method functions; same-impl-block collisions are a `compile_error!` (`check_s7_shortcut_collisions` in `miniextendr_impl.rs`). Sidecar-accessor collisions (`<ClassName>_get_<field>`) are NOT detectable at macro time — see #991. The advisory roxygen prose is shared via `s7_class::shortcut_advisory_lines`. A method whose R name is not syntactic (`r_name = "[["`) gets no shortcut; `s7_class::s7_shortcut_name` is the one rule the inherent generator, the trait generator and the collision check share.
- **Operator names are R symbols in some positions only.** Wrap assignment targets, `S7::method(<sym>, ...)` first arguments, R6 private-list element names and `Class$<member>` in `naming::r_def_name` (backticks for non-syntactic names); keep string literals and the `what` argument of `emit_method_prelude` bare. A raw `@rawNamespace export(...)` needs `naming::r_namespace_name` (`export("[[")`); `miniextendr-api`'s generic-doc pass mirrors it. S7 base operators (`[`, `[[`, `$`, `Ops`, `%*%`) attach to base's generic with no export or generic page (`s7_class::s7_generic_target`).
- **S7 dispatch arguments are name-based.** `s7_class::s7_dispatch_args` gives `s7(dispatch = "...")`, else an operator's fixed pair (`e1, e2` for `Ops`, `x, y` for `%*%`), else `x`. The first names the receiver (method formals, `<recv>@.ptr`, fallback guard, chain value); the rest must be the method's leading R formals, in order, without defaults. `check_s7_dispatch` (`miniextendr_impl.rs`) enforces that at compile time, plus one `e2`/`y` operand for operators, `!` rejected, and `no_dots` only with dispatch-only formals. Non-receiver dispatch args are `S7::class_any` in the signature.

- **Generated `@param` filler** (`(no documentation available)`, `(undocumented)`, choices text, match_arg doc placeholder) is skipped when `roxygen::params_documented_elsewhere` holds for the *author's* tags (`@rdname`, `@describeIn`, `@inheritParams`, `@inherit` with params; #1590). Feed it only doc-comment tags, plus the block's default page when known (a class generator passes the class name, so an author `@rdname <Class>` counts as no page tag): the framework's own page defaults (a standalone fn's own page, class-page `@rdname`) must keep their filler, since nothing else documents those arguments. A new per-argument filler emitter goes through the same check. Standalone fns are the exception: `push_fn_param_tags` drops fillers only for `@describeIn` / inherited params and marks the rest with `roxygen::PARAM_FILLER_MARKER`; `resolve_standalone_pages` in `miniextendr-api/src/registry.rs` decides them per page at write time (it knows every function on the page, and the file stem: an explicit `@rdname <file stem>` is the opt-in group page whose functions keep their fillers, any other `@rdname` joins a topic defined elsewhere). A free fn without a page tag documents its own page; the registry injects no `@rdname` (#1289).
- **Blocks on an author topic** (`roxygen::joins_author_topic`: `@describeIn`, or an `@rdname` naming another page than the default) must not claim the page: they drop the fixed structural `@param` lines (`x` / `...` on S3 methods and generics, `self` / `...` on S7 trait shortcuts, `.ptr` on S7 class blocks) and carry `@order NaN` (`roxygen::ORDER_AFTER_TOPIC_BLOCKS` via `push_order_after_topic_blocks` / `orders_after_topic_blocks`), which sorts them after the topic's own block so it names and titles the merged page whatever the R file order. A new generator block that follows a method onto its page (`roxygen::method_page` / `push_rdname_or_default`) needs both. A method-level `@describeIn` is only valid where the wrapper is a plain R function (`ParsedImpl::reject_unsupported_describe_in`); `MethodDocBuilder` then emits neither `@name` nor `@rdname`. Trait-impl methods forward only their `@param` lines and the page tags (`miniextendr_impl_trait/r_wrappers.rs`: `PAGE_TAGS` via `own_block_page_lines`, which plays `MethodDocBuilder`'s part for the method's own block), except that env trait methods and S3 / vctrs / S7 statics (no `\usage`) forward every other author tag but `@title` and a bare `@export` too (`roxygen::forwarded_member_tag`, which env inherent methods share: roxygen2 would export `Type$method` itself), their `@param` lines and choice text going into a `\describe{}` list via `r_class_formatter::describe_params_lines` (`forwarded_body_tag`), and S4 statics get `@param` fillers (`param_doc_tags`); their `@describeIn` rule is `r_wrappers::reject_unsupported_describe_in` (wider than the inherent one on S4 instance methods, whose trait block sits on `setMethod()`).
- **Wrapped roxygen tags:** `@title`, `@keywords`, `@concept` and `@aliases` must render on one line for roxygen2; keep them in `JOINED_TAGS`, not `MULTILINE_TAGS`. Multi-line tags keep their blank lines and indentation; render author tag text through `push_roxygen_tags*` / `roxygen_line`, never `format!("#' {}", tag)` (a wrapped tag would land in wrappers.R as bare R code, and a blank line would get a trailing space). A successful `force-document` exit does not prove the absence of roxygen diagnostics: inspect its log and the regenerated Rd fields.

## When changing codegen
- Touched proc-macro output? Run `just configure && just rcmdinstall && just force-document`. Commit regenerated `NAMESPACE` + `man/*.Rd` in the same PR. `rpkg/R/miniextendr-wrappers.R` and `rpkg/src/rust/wasm_registry.rs` are gitignored, regenerated during installs, and shipped from disk in the tarball; CI's `wrappers-sync-check` detects tracked doc drift.
- Added a class-system constructor path? Make sure error-check pattern `(.val <- .Call(...); condition_check_lines())` is wired through — silent object corruption otherwise.
- Added a S3 `@export`? Use `#' @export generic_name` (explicit target) on `if (!exists(...)) generic <- ...` — roxygen2 can't introspect conditional declarations and drifts the export onto the next function.
