# miniextendr-macros

Proc-macro crate — `#[miniextendr]`, `#[miniextendr_init]`, derives (`ExternalPtr`, `Altrep*`, `DataFrameRow`, `MatchArg*`, `Factor`, `Vctrs`, `List`, `TypedExternal`). See root `CLAUDE.md` for project rules.

## Scope
- Compile-time item codegen lives here. Registration aggregation and the
  host-side wrapper/wasm file writers live in `miniextendr-api::registry`;
  `miniextendr-engine` is only for standalone R embedding.
- Shared parser layer (formerly `miniextendr-macros-core`) is now in-crate and re-consumed by `miniextendr-lint` directly.

## Layout
- `lib.rs` — proc-macro entrypoints + the `MiniextendrFnAttrs` / `ImplAttrs` / `ParsedImpl` destructuring. **Add a field here → update all 6 class generators.**
- `naming.rs` — canonical name derivations (R wrapper names, `__miniextendr_*` mangling, class symbols). Single source of truth. All macro-emitted `#[no_mangle]` C symbols are crate-prefixed here (`C_<crate>_<fn>`, `C_<crate>_<Type>__<method>`, `__VTABLE_<crate>_…`, `__vtshim_<crate>_…`, `__mx_altrep_reg_<crate>_…`) for webR cross-package uniqueness (#1273) — never reconstruct these shapes inline; call the helpers.
- `type_inspect.rs` — shared type helpers incl. the visibility-marker peel (`peel_visibility_marker`, `peel_return_visibility`, `resolve_visibility` = marker > `invisible`/`visible` attr > shape default, `visibility_marker_error` for nested / argument-position markers, #1213). Bare fns peel in `lib.rs`; `ParsedMethod` / `TraitMethod` peel at parse time (`visibility_marker` / `invisible` fields) so every return-shape predicate sees the inner type; `MethodReturnBuilder::with_invisible` and `r_wrappers::finish_instance_body` apply the decision. Also `call_marker` (#1566): detects a bare `Call` / `CallerCall` parameter type (the condition-call markers, `MAIN_THREAD_BOUND`). `lib.rs` strips the marker from the R-facing inputs, binds it from `__miniextendr_call` at the Rust call site and resolves the attribution via `CallAttribution::resolve` (marker > `call = wrapper|caller|none` attr > crate default > `wrapper`; always the call as written); `NoCall` (`call = none`, #1851) passes `.call = FALSE` and `NULL` to the R-side checks, so every condition, argument errors included, is call-less, has no marker (a marker next to it, `call_arg` and `extern` are errors) and as the crate default `"none"` applies to every free fn; an S3 method (`s3(...)`, or an S3 impl block through `MethodContext` / `TraitMethodContext::with_call_attribution`) maps `Wrapper` to `Generic` (`for_s3_method`): `.call = environment()` into `.Call()` and the guards, resolved to the generic's call (`.Generic` for the head, `*tmp*` → the first formal, `x$f <- value` for a replacement generic) by `.miniextendr_frame_call` in `registry.rs` only when a condition is raised, or to `GenericEager` (a `.mx_call <- .miniextendr_frame_call(environment())` prelude) when the method has a `Call` parameter; a standalone wrapper resolving to `caller` gets a trailing `.call = NULL` formal (`CallAttribution::formal`, S3 methods excluded, #1613) so a hand-written helper can pass on the frame to report; `call_arg` (#1834) turns `wrapper` into `CallAttribution::Argument` (`with_call_arg`, crate default skipped), the same formal on any standalone fn with `NULL` = its own call (an inline `is.null(.call)` prelude, `.miniextendr_caller_call(.call, own = TRUE)` otherwise); refused with `caller` / `CallerCall`, `s3(...)` and `extern`. Its `@param .call` line (`push_fn_param_tags`) is no filler, so it survives a joined page, `@describeIn` and `@inheritParams`; `RustConversionBuilder` emits a `compile_error!` for a marker in any method context.
- `NArgs` (#1860): `type_inspect::is_nargs_marker` (bare last segment) marks a parameter that is no R formal. `RArgumentBuilder::build_formals` / `r_formal_names` skip it and `build_call_args_vec` passes `nargs()` in its place, so every generator (standalone, `MethodContext`, `TraitMethodContext`) gets it; `push_fn_param_tags`, `build_precondition_checks` and `check_replacement_value_param` skip it too, `nargs` is in `r_shadowing::BASE_CALLEES`, and `miniextendr_fn::check_nargs_params` (fn path in `lib.rs`, methods in `finalize_method_param_attrs`) refuses a second one and options on it; the `extern` refusal is in `MiniextendrFunctionParsed::parse`. The C wrapper converts it through `TryFromSexp` like any argument.
- `LazyDots` (#1892): `type_inspect::is_lazy_dots_marker` (bare last segment, lifetimes only) makes a parameter R's `...`, like `&Dots`: `miniextendr_fn::dots_kind` returns `DotsKind::{Forced, Lazy}`, so `find_dots_param` / `dots_index` / `has_dots` and the formals treat both alike (one `...` per function, a mixed pair gets its own message), and `RArgumentBuilder` (`dots_kind`) passes `DotsKind::r_call_arg()`, `environment()` for `Lazy`, in every generator. `RustConversionBuilder` binds it with `LazyDots::from_wrapper_arg` in every context (no `TryFromSexp`, no native-borrow query); `r_preconditions` skips it; `LazyDots` is `MAIN_THREAD_BOUND`. Refused: a non-whole type (`check_lazy_dots_params`, fn path in `lib.rs`, methods in `finalize_method_param_attrs`) and per-parameter options there, `Missing<LazyDots>` (`validate_param_type`), `dots = typed_list!` (`typed_list_on_lazy_dots`, `lib.rs` and `miniextendr_impl.rs`), trait methods (`refuse_lazy_dots_in_trait_method`, in `miniextendr_trait.rs` and the trait-impl vtable path) and `extern` (`lib.rs`).
- `crate_config.rs` — the only manifest read at expansion time: `[package.metadata.miniextendr]` in the user crate's `Cargo.toml` (via `CARGO_MANIFEST_DIR`, cached per manifest dir). Six keys: `noexport_postfix`, the crate-wide default suffix for `noexport` / `internal` free functions (#1454); `source_tags`, the opt-in for `@source` provenance lines on every generated roxygen block (off by default, #1552; every emitter goes through `roxygen::source_tag`); `call_attribution = "wrapper" | "caller" | "none"`, the crate-wide default condition-call attribution for standalone fns (#1566; `"caller"` applies to `noexport` / `internal` only; `"none"` to every free fn, #1851); `conversion_error_class = "..." | [...]`, classes appended to every argument-conversion condition after the error type's own `RConditionData` classes (read by `RustConversionBuilder::new` and the sidecar setters via `conversion_error_class()`, and by `miniextendr_init!`, which registers them in `MX_CONVERSION_ERROR_CLASS` for the wrappers preamble's `.miniextendr_conversion_error_class`, so the R-side checks raise them too, #1591); `preconditions = true | false`, the crate default of the type-derived R-side checks (`preconditions_default()`, below every item-level spelling, above the `no-preconditions-default` feature, #1566); and `roxygen_prose_links = "strip" | "keep"`, whether leading doc-comment prose keeps its `[...]` links on its way to `@description` (`roxygen::ProseLinks`, read once in `roxygen_tags_from_attrs_impl` via `roxygen_prose_links()`; default `strip`, because rustdoc and roxygen2 share the syntax and `[name()]` is a valid intra-doc link, so a heuristic can't tell them apart; only a target no R package can resolve, a `crate` / `self` / `Self` root or a `pkg::` part that is not a valid R package name (`roxygen::is_rustdoc_only_target`), loses its brackets under both settings and in non-code tag text, #1739; rustdoc's inline `[text](crate::x)` keeps only its text there too when its destination is any Rust path with a `::`, optionally behind a rustdoc disambiguator (`fn@`, ...), whatever its root, `roxygen::inline_rustdoc_destination`, #1744, #1756, while every URL and a bare `[text](Foo)` stay; a bracketed `` [`Type::method`] `` that names no declared R package is MXL204 in `miniextendr-lint`, #1742; a block that renders no page loses every link in its prose and non-code tag text whatever the setting, #1818: the reader sees the block's own `@noRd`, and a caller passes `roxygen::RdPage::Suppressed` when its attributes take the page away, `lib.rs` for `noexport`, `ParsedImpl::parse` for a class under a plain `noexport` (`ClassDocBuilder::build`'s gate) and its methods, `generate_vtable_static` for a trait impl and its methods; MXL204 skips the same blocks). Line-based scanner on purpose (no TOML dependency in a proc-macro crate); add keys there, not ad hoc. Its `normalize_key` / `parse_string_value` are mirrored in `miniextendr-lint/src/crate_root.rs` (the lint's `[lib] path` reader, #1745); keep both in sync.
- `miniextendr_fn.rs` — `#[miniextendr]` on bare fns. Tagged-condition transport is the only mode; `unwrap_in_r` is orthogonal.
- `miniextendr_impl.rs` (+ `miniextendr_impl/`) — inherent impl methods. Same transport. Class-system dispatch (R6/S3/S4/S7/Env/Vctrs).
- `miniextendr_impl_trait.rs` (+ `miniextendr_impl_trait/`) — trait-impl method codegen, ABI-compatible. Populated impls enter through the declaration's metadata macro (re-exported with the trait in the macro namespace), which supplies `r_name`, `skip` and declaration parameter names before `generate_vtable_static`; preserve impl overrides and original method signatures. Empty impls use the same macro's signature arm. The metadata also carries the declaration's canonical name, ABI fingerprint and ordered callback fields; impls reproduce that repr(C) layout locally, never guess companion paths. Non-generic shims are hidden trait methods with `Self: Sized` (preserve Rust trait objects and declaration-local type scope); generic impls retain concrete shims. Omitted defaults, of generic and non-generic traits alike, carry signatures (never bodies) through the metadata, each parameter named as the declaration's metadata names it; `miniextendr_impl_trait/defaults.rs` substitutes concrete trait arguments and feeds synthetic methods only to wrapper generation, never to the emitted Rust impl. Explicit overrides keep their own signatures/options; declaration docs and names apply to inherited defaults, and `extract_methods` gives an impl parameter written as a pattern the declaration's name. Copied signatures infer argument types from a concrete method item through `trait_signature` and the runtime `trait_abi::signature::Argument` witness (#2123): `RustConversionBuilder` (`inferred_types`) still picks each conversion from the written type and swaps only the converter at the leaf (`target.convert` / `target.rooted`, `ArgContext::with_inferred`), so no conversion kind needs a whitelist; never resolve private declaration-local aliases in the impl module, add conversion bounds to the trait, or call the method to discover its types. Conversion errors remain concrete at the call site so condition-class probes and native-borrow preflight retain their semantics. Hidden macro export names are expansion-unique because Rust exports `macro_rules!` at the crate root even for nested declarations.
- `miniextendr_trait.rs` — `#[miniextendr_trait]` declaration codegen. Trait-ABI vtable shims wrap in `with_r_unwind_protect_shim` (returns a tagged error SEXP that the View method re-panics into the consumer's outer `with_r_unwind_protect` guard) — see `generate_method_shim` there and `generate_concrete_vtable_shims` (`miniextendr_impl_trait/vtable.rs`) for generic traits. Both check arity, then refuse aliased native borrows (`trait_self_ref::native_borrow_checks`), then convert; argument conversion returns the shared structured `kind = "conversion"` condition (`shim_conversion_err_arm`, #2029); arity and alias failures panic inside that boundary, never `Rf_error`.
- `externalptr_args.rs` — borrowed external arguments (#2106): `external_arg` recognises `&T` / `&mut T` (a path `T` not in `NOT_EXTERNAL` — the reference types the conversion builder reads from R vectors — and without a `r_preconditions` type check), the views `ExternalPtrRef<'_, T>` / `ExternalPtrMut<'_, T>`, and `Option` of either. `handle_conversion` converts each to its `ExternalPtr<T>` handle with the other arguments (`from_r::__mx_external_arg::<T>`, no `T: Send` bound; `Self` replaced by the impl type; a `'static` lifetime is a `compile_error!`), and `arg_borrows` binds the parameter to `__mx_shared` / `__mx_exclusive` of a `__mx_borrow` / `__mx_borrow_mut` guard (or the view itself), which `CWrapperContext` emits after conversion and `post_conversion` (so after the receiver borrow and the trait alias asserts) and holds through return conversion. Every generated use of `T: TypedExternal` is one of those free functions with `::<T>` spanned on `T`, so a non-external `&T` is one error. `ExternalPtr<T>` parameters take no borrow. `type_inspect::is_main_thread_bound_input` counts the borrowed forms, so such a function never runs on the worker. `param_markers` names are skipped (a marker rebinds the parameter's type).
- `trait_self_ref.rs` — shared Self-reference extraction/borrowing and per-call alias checks for trait shims, plus `native_borrow_checks`, the shims' `TryFromSexp::NATIVE_BORROW` preflight (non-`Self` arguments at their original argv positions; `&Self` handles keep the address check). Preserve `&mut Self`, compare actual pointer addresses before creating references, and keep handles alive through return conversion. Shim ABI parameters, receiver references and Self-handle bindings use mixed-site spans so source parameters such as `data`, `argv` or `self_ref` cannot capture them (#1677). Pass the hygienic argument-buffer identifiers into extraction instead of spelling them again. `receiver_borrow` borrows the data's `RefCell` (`borrow_value` / `borrow_value_mut`, #1965), `borrow` takes `borrow()` / `borrow_mut()` on each `&Self` argument's handle before making its reference (#2106; a shim's by-value `ExternalPtr<T>` arguments take none), and `cell_address` gives the alias checks the value's address; bind the guard before the call and keep it through return conversion (`let result = …;`, not a block).
- `call_method_def.rs` — shared native `.Call` registration for the main wrapper builder and sidecar accessors. Callers supply the complete C arity; registration must not infer or add a call slot. Keep the registration name equal to the linker symbol for wasm reconstruction.
- `c_wrapper_builder.rs` (+ dir) — `CWrapperContext` for impl method C wrappers. **Prepends `__miniextendr_call: SEXP` as first param.** The worker wrapper runs the body under `condition::catch_condition` on the worker and turns a caught `RCondition` into its tagged value on the main thread (`error_value::rust_condition_value`), so immediate conditions keep their kind, classes, data and call choice there.
- One return rule for standalone fns, inherent methods and trait methods: `c_wrapper_builder::detect_return_handling(output, wrap)` (#1415, #2088). Every `Option<T>` is `OptionIntoR` (the whole `Option`'s `IntoR`: `NULL` / `NA` per impl) except `Option<()>` / `Option<SEXP>` (raise, both paths: `NULL` there can't be told apart from `Some`), a method's `Option<Self>` (`OptionExternalPtr`: `Some` becomes `ExternalPtr::new`, then `IntoR for Option<ExternalPtr<T>>`, so `None` is `NULL`; the fallible step `SelfHandleOption` likewise) and an explicit `Option<Class>` wrap (`OptionClassPayload`: converts the payload, `None` is `NULL`; `ReturnWrap::is_optional_class`), since no `IntoR for Option<Class>` can exist; a user spells an optional class `Option<ExternalPtr<Class>>` or wraps it explicitly. Never add a type whitelist or a fn/method split back. The R side lets `NULL` through every class wrap of an `Option` return: `ReturnWrap::r_expression` and `MethodReturnBuilder::null_passes` (`ParsedMethod::returns_option`) emit `if (is.null(.val)) NULL else <wrap>`, so `lapply` never turns `NULL` into `list()`, and the `ReturnSelf` / `ChainableMutation` tails return `NULL` before the class wrap or receiver (`MethodReturnBuilder::with_nullable` for trait methods); the registry resolvers stay unchanged. A return that is `NULL` for `None` whatever `T` is (`RIterator::next` / `nth`) uses the API type `Nullable<T>`, a plain `IntoR` return: never special-case a trait or method in the detector.
- `externalptr_derive.rs` — hand-rolls C wrappers for sidecar `*_get_field` / `*_set_field` accessors: `(x: SEXP, require_live: SEXP)` / `(x, value: SEXP, require_live: SEXP)`, `numArgs = 2/3`, **no call slot**. Adding a `.call` argument to the R side breaks at runtime (PR #344 reverted this). The trailing `require_live` flag (#1891) is how the generated field methods refuse a restored pointer with one accessor per field and no extra `.Call()`: the `.rdata_get/set_<Type>` arms pass `TRUE`, the standalone `Type_get_f()` / `Type_set_f()`, the R6 bindings and the S7 properties pass `FALSE` and keep reading a same-version save's `Sidecar` values; only a `Sidecar` slot reads it (`externalptr::sidecar_require_live` → `checked_prot`, which calls `refuse_restored` on a NULL address when set), the other kinds take it as `_require_live`. A `Sidecar<T>` field (`SlotKind::Sidecar(index)`, numbered among the `Sidecar` fields only; `sidecar_inner_type` recognises the type by its last path segment) reads and writes the pointer's `prot` list through `externalptr::sidecar_r_get` / `sidecar_r_set` (the setter validates with `TryFromSexp::<T>` first, after `sidecar_r_check`); the derive also emits `TypedExternal::R_SLOT_COUNT`, the hidden `__mx_visit_sidecars` hook (index, name, `&dyn SidecarField` per field), and typed Rust accessors as associated functions taking an owner (`fn f(ptr: &impl SidecarOwner<Self>) -> T` / `fn set_f(ptr: &mut impl SidecarOwnerMut<Self>, value: T)`; the owners are `ExternalPtr` and the views `ExternalPtrRef` / `ExternalPtrMut`, through `externalptr::sidecar_get` / `sidecar_set` with a field-selector closure, which borrow through the owner's hidden `__mx_read` / `__mx_write`; no accessor on `&self`, #1856) with the field's visibility selected by `#[r_data(ref)]` / `#[r_data(mut)]` / both (`RDataArg`, `SidecarAccess`; a `Sidecar<T>` field without `#[r_data]`, or `ref` / `mut` on a non-`Sidecar` field, is a compile error). Known bare R views (`SEXP`, `List`, `DataFrame`, etc.) under `#[r_data]` are compile errors pointing at `Sidecar<T>` (#1962); `contains_unrooted_r_view` follows standard containers, arrays and tuples, while owned roots and opaque user types keep their existing conversion path. Aliases cannot be inspected syntactically. A `Computed` marker field (`SlotKind::Computed(path)`, `#[r_data(get = "Self::f")]`, #1883; `is_computed_type` by the last path segment, `computed_getter_path` rewrites a leading `Self`) gets a getter whose body is `IntoR::into_sexp(path(data))` on the live struct, no setter C fn / `CallDef` / `Type_set_f()` (`generate_setter_body` is empty for it), and a `.rdata_set_<Type>` arm that `stop()`s with `miniextendr_read_only_field` and `.miniextendr_frame_call(parent.frame())`; `get` on another type, no `get`, `ref` / `mut` / `setter` on it, a non-`pub` one, or one under `r6` / `s7` (#1888) is a compile error. `#[r_data(name = "...")]` sets `SidecarSlot::r_name` (#1891), used by every R-facing string (`.rdata_fields_<Type>`, the switch labels and the `no_field` listing, the R6 binding / S7 property and its `SidecarPropEntry::field_name`, the setter's `'name' must be` message, the standalone `Type_get_<name>()` / `Type_set_<name>()`); the C symbols, the `__MX_CALL_DEF_RDATA_*` / `__MX_S7_SIDECAR_PROP_*` statics and the Rust accessors keep the Rust identifier (an R name may hold a `.`, which `Ident::new` refuses). A `Sidecar` field's save slot is named by the R name too (`SIDECAR_NAMES`, the name `__mx_visit_sidecars` and every Rust accessor pass, #2215): it is the save format, so renaming the Rust field keeps earlier saves readable and renaming the R name orphans their slots. Refused: an empty name, a non-syntactic one (`naming::is_syntactic_r_name`), `.ptr`, a duplicate among the type's R names, and `name` on the selector. `#[externalptr(restored(class = "..." | ["...", ...], message = "..."))]` (`RestoredOptions`, parsed next to the class system by `parse_externalptr_attrs`) emits `TypedExternal::RESTORED_ERROR_CLASS` / `RESTORED_ERROR_MESSAGE`, which `refuse_restored` and `TypeMismatchError` read. Its `refuse = "every_read"` (#1901, `RestoredOptions::every_read`) emits one more C fn per type (`naming::sidecar_live_c_name`, `externalptr::sidecar_r_live`) bound as `.rdata_live_<Type>` and gated by `.rdata_every_read_<Type>` (`TRUE` / `FALSE`; without the option `.rdata_live_<Type>` is a never-called stub function, since `R CMD check` notes a call to a `NULL` binding), which the field methods call before `names()` and an unknown name, and `.DollarNames()` with `raise = FALSE`. `field_error(class = ...)` (#1899, `parse_field_error_options`) emits `TypedExternal::FIELD_ERROR_CLASS` (the receiver's type-mismatch and no-handle refusals in `externalptr/sidecar.rs`) and `.rdata_error_class_<Type>` (else `NULL`: the `no_field` / read-only arms and `.miniextendr_field_at`). The standalone accessors go to a `SidecarAccessorsEntry` (`registry::MX_SIDECAR_ACCESSORS`) in an exported and an internal (`@noRd`) rendering; the wrapper writer picks internal when a `ClassNameEntry` of the type has `field_syntax` (S3/S4/env `r_data_accessors`), since the impl is a separate expansion (#1900). The field methods' page is the impl's `@rdname`, else the class page (`field_syntax::topic` / `page_lines`: on an author topic no `@param` and `@order NaN`). The internal rendering also carries the field-syntax helpers `.rdata_{fields,get,set,no_field}_<Type>` (`naming::rdata_helper_name`; a `switch()` over the accessors' `.Call`s and the classed `miniextendr_no_field` error) that `s3(r_data_accessors)`, `s4(...)` and `env(...)` (`miniextendr_impl/field_syntax.rs`, #1848) call from `$` / `[[` / `$<-` / `[[<-`; the class blocks check at load time that they exist. Classes without field syntax omit this helper family; R6 / S7 integration stays in its own fragment. `RDataAccessors` (`Off` / `GetSet` / `GetOnly`, `= "get"` on S3, S4 and env only) replaces the old bool; `field_syntax::check_collisions` refuses an impl method on a generated generic.
- `miniextendr_impl/field_syntax.rs` — the class-side field methods (#1848, #1891). No reader matches a prefix (#1922): never emit `pmatch`/`charmatch`/`match.arg`, a `$` on a list receiver goes through `.subset2()`, and `[[` falls through with `NextMethod(exact = TRUE)`. On an S3 bare pointer the default lookup (`FieldLookup::Strict`, #1921) takes an exact name (else `miniextendr_no_field` naming the R class) or a whole-number position through the preamble helper `.miniextendr_field_at` (`registry::FIELD_AT_HELPER`: R's own `[[` on the field-name vector, `subscriptOutOfBoundsError` past the end and for `0` / negative, the generic's call); any other index raises `.miniextendr_field_index_error` (the `field_error` classes + `notSubsettableError`, #1920). `s3(r_data_accessors, lookup = "list")` (`FieldLookup::List`) reads `NULL` for an unknown name or `NA` and takes a logical or fractional position as a list does. Under `restored(refuse = "every_read")` every S3 reader starts with `Helpers::every_read_check` on a pointer, list or environment receiver (#1919). The S3 class also gets `names()` / `as.list()` (bare pointer only, `NextMethod()` on a list receiver and `as.list.environment()` by name on an env one, whose class attribute would send `NextMethod()` to `as.list.default()`; `as.list()` keeps a `NULL` field with `out[k] <- list(.val)`; #1890) and `.DollarNames()` (#1885), which S4 and env classes get too (`dollar_names_doc`, `env_dollar_names`): registered with `@exportS3Method utils::.DollarNames` (qualified `S3method(utils::.DollarNames, Class)`), never the `@method` + `@export` pair, whose unqualified entry fails to load under `R_DEFAULT_PACKAGES=NULL`. New unqualified callees in the generated text go in `r_shadowing::BASE_CALLEES` (the `generated_callees_are_listed` test). An S3 impl needs no constructor or methods (`impl Engine {}` with `class = "..."`): a package that classes the pointer itself still gets the readers. A field fallback (`s3/s4/env(r_data_accessors, fallback = "Self::f", fallback_names = "Self::g")`, `FieldFallback`, #2150) gets two `.Call` entries from the impl expansion (`fallback_c_entries`, `naming::sidecar_fallback_c_name` / `sidecar_fallback_names_c_name`; the sidecar getters' kind: no call slot, `sidecar_r_struct` borrow, so a restored pointer is refused before the function runs). The readers call it on the bare pointer only, after the fields (and an env class's methods), passing their own frame as the `None` sentinel, which the entry returns untouched (`identical()` on the R side, no SEXP held across an allocation); `None` then reads what an unknown name reads (`miniextendr_no_field`, or `NULL` under `lookup = "list"` and on env). The names entry gives `character(0)` without a live value, so `.DollarNames()` never raises. It is not a class setting: `ParsedImpl::class_definitions` lists it ("the field fallback"), so only the defining block carries it and its head calls it.
- `r_wrapper_builder.rs` (+ dir) — R-side `.Call(C_…, .call = sys.call(), …)` emission (the call as written). `DotCallBuilder` at ~L390 is the canonical site; use `.null_call_attribution()` for lambda contexts (R6 finalizer/deep_clone, S7 getter/setter/validator) and `.with_call_attribution(CallAttribution::Generic)` for S3 class methods (`.call = environment()`, #1851). `CallAttribution` holds every call-slot spelling: `dot_call_arg` / `dot_call_expr` (the `.Call()` slot), `r_check_call` (the guards' and choice helpers' call argument), `raise_default` (the raise helper's fallback), `prelude`, `formal`; add a variant there, not inline.
- `r_class_formatter.rs` — shared `MethodContext` for all 6 class generators.
- `return_type_analysis.rs` — return-type → codegen for standalone fns (strict-aware).
- `method_return_builder.rs` (+ dir) — same for impl methods.
- `rust_conversion_builder.rs` (+ dir) — TryFromSexp glue for argument conversion. Every binding is a typed `let` (borrowed slices / `&str` with lifetimes erased via `type_inspect::erase_lifetimes`), because the shared `Err` arm (`conversion_err_arm`) probes the error type by method call (`__mx_conversion_err_parts!(e, expected_known)`: `RConditionData` class/message/data, the R-worded reason of a built-in `SexpError`, else `Display`) and `conversion_condition_value` adds the R-terms prefix from `ArgContext` (`'<p>' must be <expected>` via `r_preconditions::conversion_expectation`, else `invalid '<p>' argument`), the crate class, `e$param` and `e$rust_type` (`type_inspect::type_display`) (#1591). Where the prefix is not a literal, the arm also passes `__mx_conversion_arg_message!(e, <name>)`: a `match_arg` choice error then replaces `<prefix>: <reason>` with the R-side `match_arg` check's own message (#1767). ## Gotchas specific to this crate
- **Trait View pointers live in runtime `TraitViewData`.** Generated views must not expose writable data/vtable fields, even as private fields in the consumer's module. `try_from_sexp` passes the receiver as owner to `from_raw_parts`; the runtime roots it until the view drops. The raw constructor accepts `None` only with a caller-provided data lifetime. Keep the no-arg `gc_stress_trait_view_args` fixture using its View after its temporary owner root ends.
- **Generated Rust item names preserve identifier case.** Use the `naming.rs` helpers for tags, builders, shims, vtables and registration statics in both ordinary and trait-provided impl expansion. Keep the crate prefix and generic-type hash; never fold `Counter` and `counter` together to satisfy a naming lint. Apply style allowances to generated items instead. ExternalPtr constructor helpers, base vtables and sidecar registration names keep both type and field case too (`__mx_wrap_Counter`, `__MX_BASE_VTABLE_Counter`). Erased storage and its destructor live once in runtime `abi::ErasedObject<T>`; do not emit per-type wrapper structs or drop functions. Wrapper registration statics also preserve function/type names. An impl block's class registrations (`ClassBlockEntry`, `ClassNameEntry`) sit in an anonymous `const _`, and its C wrappers are `C_{crate}_{Type}__{method}`, so any number of impl blocks of one type expand side by side (#1776).
- **Generated wrapper bindings must not capture source parameters.** Generated raw C argument slots (`arg_N`), receiver handles/references and conversion temporaries use mixed-site spans. The shared `naming::self_sexp_ident` connects the C signature, method extraction and chained-return paths; interpolating a source-spanned parameter with the same spelling must still refer to the user's value. A mixed-site span takes this crate's edition (2024), so never re-span an identifier the user spelled (an edition-2021 crate's `gen` turns into a reserved keyword); synthesize a name instead. Preserved standalone parameter names keep their own span. Keep the compile-pass fixtures (`tests/ui/pass/{c_wrapper,trait_shim,macro_rules}_binding_hygiene.rs`) and rpkg's runtime cases (`binding_hygiene_tests.rs`, the worker `&str` case in `worker_tests.rs`) covering new bindings (#1677).
- **Generated standard-library references need absolute paths.** Generated code lands in the consumer's module, which can shadow any prelude name (`Vec`, `Default`, `Iterator`, `Send`, ...), any std macro (a `macro_rules! vec` above the invocation) and the `std` / `core` roots (a `mod core`). Spell every emitted reference `::core::...` / `::std::...`, macros included (`::core::concat!`, `::std::vec!`, also inside `#[doc = ...]`), in `quote!` bodies here and in `miniextendr-api`'s exported `macro_rules!`; leave interpolated user types/names intact. Shadowing a trait's name doesn't break method calls (the prelude trait stays in scope), but imported blanket traits can add a second method or beat an inherent method behind `Deref` / slice unsizing. Call standard trait methods fully qualified (`::core::clone::Clone::clone(&x)`) and use explicit slice access in generated code (#2020). Public adapter traits now use `r_` methods and `AltrepLen` uses `altrep_len` / `altrep_is_empty` (#2064), preserving user code under root/prelude globs. `tests/ui/pass/shadowed_standard_names.rs` (shadows) and `glob_import_method_calls.rs` (the glob) both include `common/every_macro.rs`, which invokes every derive, attribute and function-like macro; rpkg's `shadowed_std_names_tests.rs` and `glob_import_tests.rs` do the same for the worker, vctrs, rayon and serde paths. Add a new macro, option or feature-gated branch to `every_macro.rs` or the rpkg modules.
- **RNativeType requires `#[repr(transparent)]`.** Its pointer casts expose R's inner-type allocation as slices of the newtype. A one-field `repr(Rust)`, packed, or over-aligned struct does not establish that contract; reject it before generating the impl.
- **Native NA capability is separate from storage.** `#[derive(IsNA)]` forwards through `newtype_derive`'s existing parser and preserves bounds; it requires both a native wrapper and an NA-capable inner field. Do not add an unconditional IsNA impl to RNativeType derive: raw `u8` and native wrappers around it have no NA.
- **Worker shared references borrow owned storage.** `worker_string_storage` and `worker_native_storage` in `rust_conversion_builder.rs` split conversion from borrowing. Native scalars/slices (including optional forms) validate through `TryFromRoot` on R's thread before copying, preserving exact scalar lengths and NULL/NA semantics. Only owned Rust data crosses into the closure; form references there with erased source lifetimes. The borrow is of a local copy, so a `'static` lifetime there gets `static_rooted_view_binding`'s error too. Mutable native inputs retain their write-through path pending #1427.
- **Native-borrow metadata follows the selected converter.** `Call`/`CallerCall` do not convert from SEXP; omit their metadata query so method rejection keeps its intended diagnostic. `CoercionMapping::Numeric` delegates to `TryFromSexp`, so preserve its `NATIVE_BORROW`; only coercion helpers that bypass that trait omit the query. Keep minimal-feature UI coverage alongside full-feature Clippy.
- **Two C-wrapper codegen paths with different signatures.** `c_wrapper_builder.rs` prepends `__miniextendr_call: SEXP` for all `#[miniextendr]` fns/methods; `externalptr_derive.rs` does NOT for sidecar accessors. Don't unify R-side emission without unifying C-side first (#348).
- **`#[miniextendr]` on 1-field structs is removed.** Use ALTREP derives instead.
- **Lifetime params ARE allowed on `#[miniextendr]`.** Lifetimes are erased at codegen — `#[no_mangle] extern "C-unwind" fn f<'a>(...)` produces a single monomorphic symbol and is FFI-safe. Only type/const generic params are rejected (they require monomorphization → multiple symbols → incompatible with `#[no_mangle]`). Borrowed fields on `#[derive(DataFrameRow)]` structs also work (`Vec<Option<&str>>` / `Vec<Option<&[T]>>` companion columns since PR #465).
- **`impl Trait` argument position fails** (E0283 — `TryFromSexp + Trait` across `let` bindings). Return position works.
- **When changing helpers from `TokenStream` → `Result<TokenStream>`, update every caller with `?`.** Otherwise you'll see confusing `ToTokens` bound errors on `Result`.
- **UI test `.stderr` files** must be regenerated when error wording changes (`TRYBUILD=overwrite cargo test -p miniextendr-macros`). **Never overwrite under a `rust-src`-equipped toolchain** — it bakes stdlib spans into the snapshot that CI's minimal stable never renders (#1239). Run the suite via `just test-ui` (auto-isolates under a minimal-profile toolchain) and see root CLAUDE.md "UI test snapshots".
- **MXL111** — `s4_*` method name on `#[miniextendr(s4)]` impl gets `s4_s4_*`. Drop the prefix. The default generic is `s4_<R method name>` (`s4_class::s4_generic_name`: `r_name`, `postfix` and raw identifiers count, an explicit `s4(generic = ...)` is used verbatim), but the lint still reads the Rust identifier; moving it into the macro is #1770.
- **Class member collisions within one impl block** (#1677). Each check follows the generator's own method iterators and R names (`r_name`, `postfix`, `r6(prop)`), so only emitted members count and ignored methods don't: `check_env_member_collisions` (Env constructor `new`, instance and static names share the class env), `check_r6_initialize_collision` (an instance method or active binding named `initialize`), `check_r6_static_collisions` (a static method replacing one of the R6 generator object's own bindings, `R6_GENERATOR_BINDINGS`) and `check_s4_generic_collisions` (two `setMethod()`s on one generic for the class). The checks see one impl block; the wrapper writer compares the blocks of a type (`registry::merge_class_blocks`, a member bound twice via `ClassWrapper::member_names`, #1776).
- **The constructor** is `ParsedImpl::constructor()`: `declared_constructor()` (a `<system>(constructor)` marker, else a receiver-less `new -> Self`) or `inferred_constructor()` (the block's one `constructor_candidates()` entry; `Result`/`Option<Self>`, S7 `convert_from` and vctrs never count). Test membership with `is_method_constructor(m)`, not the method's own attrs. `expand_impl` renders an inferring block twice, the second time with `constructor_demoted` set, so the wrapper writer can pick per type (`registry::resolve_class_constructor`). A constructor whose R name isn't `new` is also in `static_methods()` (its own-name alias, documented through `static_doc_tags()`). Without a constructor (no candidate) no generator writes one; R6's `initialize` and S7's `constructor`, which the factories call with a `.ptr`, start with `no_constructor_guard()`.
- **S7 fast-path shortcuts** — every non-fallback S7 instance method (inherent *and* trait impl) emits a `<ClassName>_<method>(.mx_self, ...)` function that bypasses `S7::S7_dispatch()`. Opt out per-method with `#[miniextendr(s7(no_shortcut))]`. Shortcut names share a namespace with static-method functions; same-impl-block collisions are a `compile_error!` (`check_s7_shortcut_collisions` in `miniextendr_impl.rs`). Sidecar-accessor collisions (`<ClassName>_get_<field>`) are NOT detectable at macro time — see #991. The advisory roxygen prose is shared via `s7_class::shortcut_advisory_lines`. A method whose R name is not syntactic (`r_name = "[["`) gets no shortcut; `s7_class::s7_shortcut_name` is the one rule the inherent generator, the trait generator and the collision check share.
- **Operator names are R symbols in some positions only.** Wrap assignment targets, `S7::method(<sym>, ...)` first arguments, R6 private-list element names and `Class$<member>` in `naming::r_def_name` (backticks for non-syntactic names); keep string literals and the `what` argument of `emit_method_prelude` bare. A raw `@rawNamespace export(...)` needs `naming::r_namespace_name` (`export("[[")`); `miniextendr-api`'s generic-doc pass mirrors it. S7 base operators (`[`, `[[`, `$`, `Ops`, `%*%`) attach to base's generic with no export or generic page (`s7_class::s7_generic_target`).
- **S7 dispatch arguments are name-based.** `s7_class::s7_dispatch_args` gives `s7(dispatch = "...")`, else an operator's fixed pair (`e1, e2` for `Ops`, `x, y` for `%*%`), else `x`. The first names the receiver (method formals, `<recv>@.ptr`, fallback guard, chain value); the rest must be the method's leading R formals, in order, without defaults. `check_s7_dispatch` (`miniextendr_impl.rs`) enforces that at compile time, plus one `e2`/`y` operand for operators, `!` rejected, and `no_dots` only with dispatch-only formals. Non-receiver dispatch args are `S7::class_any` in the signature.
- **Existing S3/S4 generics own their formals.** Inherent and trait methods share `generic`, `receiver`, `no_dots` (`receiver` / `no_dots` need `generic` and an instance method): use the selected receiver for collision checks, pointer extraction, chaining and docs; a named S4 signature (`c(object = "T")`) binds it explicitly. An explicit generic is never exported or given a generated page; an explicit S4 one is defined only when no function and no other package's generic of that name is visible (`s4_class::s4_generic_guard`: `exists()` sees `length` / `summary`, `methods::isGeneric()` sees `show` when `methods` is not attached, and a generic whose `@package` is this namespace's name is an attached installed copy's, so it does not count, #1158), the package's own `s4_<name>` behind the namespace-local `exists()` (#1158). `r_class_formatter::instance_formals` keeps an explicit `...` and adds the dispatch dots at most once.

- **Generated `@param` filler** (`(no documentation available)`, `(undocumented)`, choices text, match_arg doc placeholder) is skipped when `roxygen::params_documented_elsewhere` holds for the *author's* tags (`@rdname`, `@describeIn`, `@inheritParams`, `@inherit` with params; #1590). Feed it only doc-comment tags, plus the block's default page when known (a class generator passes the class name, so an author `@rdname <Class>` counts as no page tag): the framework's own page defaults (a standalone fn's own page, class-page `@rdname`) must keep their filler, since nothing else documents those arguments. A new per-argument filler emitter goes through the same check. Standalone fns are the exception: `push_fn_param_tags` drops fillers only for `@describeIn` / inherited params and marks the rest with `roxygen::PARAM_FILLER_MARKER`; `resolve_standalone_pages` in `miniextendr-api/src/registry.rs` decides them per page at write time (it knows every function on the page, and the file stem: an explicit `@rdname <file stem>` is the opt-in group page whose functions keep their fillers, any other `@rdname` joins a topic defined elsewhere). A free fn without a page tag documents its own page; the registry injects no `@rdname` (#1289).
- **Impl topics include members from every block (#2068).** Inherent member documentation marks generated page/parameter/prose defaults with `CLASS_MEMBER_DEFAULT_PREFIX` (`member_default`, `push_member_rdname`, `MethodDocBuilder`). `registry::resolve_class_member_docs` resolves them after merging the type's blocks, using the defining block's `@rdname`. Do not substitute the local block's topic at macro time in `members`: another block may define the class. (`head` / `tail` come only from the defining block, so `field_syntax::topic` may read its own block's `@rdname` there.) Explicit method pages remain unmarked and win; inherited author topics drop generated parameters/prose and sort after the author's topic. S7 shortcuts follow their method's page too. Trait impl wrappers are not class blocks and still default to `@rdname <Type>` (#2144).
- **Blocks on an author topic** (`roxygen::joins_author_topic`: `@describeIn`, or an `@rdname` naming another page than the default) must not claim the page: they drop the fixed structural `@param` lines (`x` / `...` on S3 methods and generics, `.mx_self` / `...` on S7 trait shortcuts, `.ptr` on S7 class blocks) and carry `@order NaN` (`roxygen::ORDER_AFTER_TOPIC_BLOCKS` via `push_order_after_topic_blocks` / `orders_after_topic_blocks`), which sorts them after the topic's own block so it names and titles the merged page whatever the R file order. A new generator block that follows a method onto its page (`roxygen::method_page` / `push_rdname_or_default`) needs both. A method-level `@describeIn` is only valid where the wrapper is a plain R function (`ParsedImpl::reject_unsupported_describe_in`); `MethodDocBuilder` then emits neither `@name` nor `@rdname`. Trait-impl methods forward only their `@param` lines and the page tags (`miniextendr_impl_trait/r_wrappers.rs`: `PAGE_TAGS` via `own_block_page_lines`, which plays `MethodDocBuilder`'s part for the method's own block), except that env trait methods and S3 / vctrs / S7 statics (no `\usage`) forward every other author tag but `@title` and a bare `@export` too (`roxygen::forwarded_member_tag`, which env inherent methods share: roxygen2 would export `Type$method` itself), their `@param` lines and choice text going into a `\describe{}` list via `r_class_formatter::describe_params_lines` (`forwarded_body_tag`), and S4 statics get `@param` fillers (`param_doc_tags`); their `@describeIn` rule is `r_wrappers::reject_unsupported_describe_in` (wider than the inherent one on S4 instance methods, whose trait block sits on `setMethod()`).
- **Wrapped roxygen tags:** `@title`, `@keywords`, `@concept` and `@aliases` must render on one line for roxygen2; keep them in `JOINED_TAGS`, not `MULTILINE_TAGS`. Multi-line tags keep their blank lines and indentation; render author tag text through `push_roxygen_tags*` / `roxygen_line`, never `format!("#' {}", tag)` (a wrapped tag would land in wrappers.R as bare R code, and a blank line would get a trailing space). A successful `devtools-document` exit does not prove the absence of roxygen diagnostics: inspect its log and the regenerated Rd fields.
- **ALTREP owner storage shares the ExternalPtr generator.** `generate_altrep_storage` emits `TypedExternal` plus Rust sidecar accessors only; do not invoke the whole ExternalPtr derive (it adds a conflicting IntoR marker, an erased ABI wrapper and R field wrappers). `#[r_data]` there accepts Sidecar fields with `ref` / `mut`. A sidecar callback uses `manual, no_lowlevel` and explicitly extracts its data1 handle. Keep ALTREP's class display name separate from its crate/version-qualified Rust type identity.
- **Owner-bearing trait receivers:** `trait_receiver` recognizes `self: ExternalPtrRef<'_, Self>` and `ExternalPtrMut<'_, Self>` and rewrites only the emitted Rust trait/impl to an associated function; preserve the original receiver signature in TPIE metadata. Declaration shims, concrete generic shims and `.Call` wrappers must all construct the handle after alias preflight. Only these methods use `mx_owner_meth`; their trait tags include the owner-receiver shapes, and a raw View without an R owner refuses them. Use `receiver_body` for both inherent and trait methods: rewrite expression `self` and macro arguments, preserve `self::` module paths and nested items with independent receivers, and retain the binding mutability of a by-value handle.
- **Borrowed `StrVec` / `RCow` / `Cow` inputs use `Root<'call>`.** Their raw borrowing `TryFromSexp` impls are gone (#1427): `StrVec` / `RCow` have none, and raw `Cow` conversions own their data. `RustConversionBuilder` binds each such parameter to its own `ProtectScope` (`__mx_roots_<name>`) and calls `<T as TryFromRoot<'_>>::try_from_root(scope.rooted(slot))` on the C wrapper's argument; both trait shim generators use `trait_self_ref::argument`, which does the same after the arity check. The scope lives through the call and return conversion and retains any element an ALTREP accessor returns during conversion; a worker copy uses a block-local scope that ends before dispatch. Never hand out a `Root` without a scope: borrowing directly from `*argv.add(i)` would fabricate another unconstrained lifetime. Preflight reads `TryFromRoot::NATIVE_BORROW`, so `RCow` and native `Cow` keep their alias checks, and rooted inputs (including `Vec<Cow<str>>` / `Vec<Option<Cow<str>>>`) stay on R's main thread. A rooted parameter naming `'static` anywhere in its type (`Option<&'static str>`, `Vec<Cow<'static, str>>`) gets `type_inspect::static_rooted_view_binding`'s `compile_error!` at the lifetime in both paths (the borrow checker would only blame a generated temporary). Only the bare view is recognized: wrappers (`Missing`, `Either`, `Result<_, ()>`) and trait returns of a view have no rooted conversion (#2038); `type_inspect::is_rooted_reference` extends the main-thread/trait-shim conversion to explicit shared native scalars/slices and strings, plus their `Option` and nested `Vec` forms. It matches by name, so a user type named `RLogical` lands there too; the API's blanket `TryFromRoot` for references runs the user's own `TryFromSexp` (`tests/ui/pass/native_borrow_metadata.rs`). Keep it separate from `is_rooted_view` so worker dispatch stays unchanged (character borrows use owned worker storage), and preserve `match_arg(several_ok)`'s owned selection storage. `worker_string_storage` keeps `&str`, `Option<&str>`, `Vec<&str>` and `Vec<Option<&str>>` in their owned string forms until dispatch, then borrows inside the worker closure; Rust marking `&str` as `Send` does not root its CHARSXP. Keep the original parameter type in conversion diagnostics and wrap parameter markers after that inner borrow. Mutable references, aliases, other containers and nested worker borrows remain #1427.

## When changing codegen
- **Member gates precede expansion (#2107).** `expand_miniextendr` first calls `cfg_gates::select`: an attribute macro gets its item unconfigured, so the first `cfg` / `cfg_attr` on a member (fn parameter, impl or trait item, enum variant, struct field) re-enters `#[miniextendr]` on two copies of the item under `#[cfg(pred)]` / `#[cfg(not(pred))]`, and rustc keeps one. Every later stage sees only enabled members, so constructor inference, S7 properties, collisions, formals, factor levels, R text and native registration agree. Do not copy member gates onto generated items instead, and do not split gated methods into separately registered class blocks. Gates on the item itself are evaluated by rustc or forwarded (`extract_cfg_attrs`, `ParsedImpl::cfg_attrs`). `tests/ui/pass/cfg_gates.rs` covers each site.
- **Struct factor fields (#2025):** resolve `as_factor` before ordinary struct flattening, using the same validation as enum fields. Companions keep owned values; `FactorVec<T: UnitEnumFactor>` builds and reads the column without `Clone`/`Copy`. Keep factor fields reader-capable and use the sequential reader for parallel reconstruction, so the annotation never adds a `Clone` bound. Cover both static and dynamic column assembly.
- **Dataframe companion lifetimes (#2028):** column expansion can erase a row borrow (`&[T; N]`, `width` over `&[T]`); skipped fields can erase one too. The shared companion marker records only missing lifetimes, including in the rows iterator. Keep it out of R columns and row counts, initialize it in sequential/parallel construction, and gate enum readers on `!borrowed` just as struct readers are gated.
- **Struct-mode helper attributes (#2024):** list and dataframe shorthands emit normal derive invocations so rustc registers their helper attrs. Do not replace this with direct derive-helper calls plus attribute stripping: another derive may need the same attrs. Explicit and `prefer = "..."` spellings share the path. Dataframe mode derives only `DataFrameRow`; opt into row-level `IntoList` separately. Companions already have `IntoR` and need no preference derive (#2026).
- **Inherent static methods follow worker selection (#2031).** `MethodAttrs::unsafe_main_thread` defaults to false; the generator already falls back to main when `worker` is false. An implicit forced-main flag would erase both `env(worker)` (and the other class spellings) and `worker-default`. Constructors count as static methods and must return `Send` values when dispatched; `no_worker` / explicit main-thread overrides keep non-Send constructors local. Receiver and dots methods stay on main, and so does a static method (inherent or trait) that takes or returns an R value or sets `check_interrupt`: `type_inspect::signature_holds_r_values` applies the standalone function rule.
- **Error messages use the resolved R name.** Feed every `CWrapperContext` builder the same name as the R wrapper (`r_name`, explicit or crate-default `postfix`, S3 name); inherent and trait methods use `r_method_name()`. Keep the Rust identifier for calls and C symbols. Return analysis takes the resolved name too; renaming must not change Option absence semantics.
- Touched proc-macro output? Run `just configure && just rcmdinstall && just devtools-document`. Commit regenerated `NAMESPACE` + `man/*.Rd` in the same PR. `rpkg/R/miniextendr-wrappers.R` and `rpkg/src/rust/wasm_registry.rs` are gitignored, regenerated during installs, and shipped from disk in the tarball; CI's `wrappers-sync-check` detects tracked doc drift.
- Added a class-system constructor path? Make sure error-check pattern `(.val <- .Call(...); condition_check_lines())` is wired through — silent object corruption otherwise.
- Added a S3 `@export`? Use `#' @export generic_name` (explicit target) on `if (!exists(...)) generic <- ...` — roxygen2 can't introspect conditional declarations and drifts the export onto the next function.
