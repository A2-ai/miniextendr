# miniextendr-api

Runtime crate — FFI, ExternalPtr, ALTREP, worker thread, error/condition transport. See root `CLAUDE.md` for project-wide rules.

## Scope
- All R API contact lives here. Macros generate code that calls into this crate.
- No proc-macros — those are in `miniextendr-macros`. Registry serialization
  for R wrappers and the wasm snapshot lives in `registry.rs` here;
  `miniextendr-engine` only embeds R for standalone Rust binaries/tests.

## Architecture pointers
- `registry.rs` — linkme `#[distributed_slice]` declarations (`MX_CALL_DEFS`, `MX_MATCH_ARG_CHOICES`, `MX_R_WRAPPERS`, `MX_CLASS_NAMES`, …) + the `miniextendr_write_wrappers` / `miniextendr_write_wasm_registry` entry points.
- `init.rs::package_init()` — consolidates `R_init_<pkg>` steps; `miniextendr_init!` proc-macro thin-wraps it.
- `mx_abi.rs` — Rust reimpl of `mx_wrap`/`mx_get`/`mx_query`/`mx_abi_register` (replaced the old `mx_abi.c` / `entrypoint.c`).
- `worker.rs` — worker thread + `Sendable<T>`. Without `worker-thread` feature, `run_on_worker(f) → Ok(f())` inline. On wasm the feature stays *enabled* but every spawn path is gated `not(target_family = "wasm")` so it also runs inline (see wasm gotcha below).
- `unwind_protect.rs` — `R_UnwindProtect` wrapper; `with_r_unwind_protect` is the user-facing path (returns a tagged-condition SEXP; the R wrapper raises). `with_r_unwind_protect_or_raise` is the panics-as-R-error variant (ALTREP `RUnwind` guards via `with_r_unwind_protect_sourced`, tests, benches): `raise_rust_condition_via_stop` builds the tagged value the wrapper would get and `Rf_eval`s the shared `.miniextendr_raise_condition` closure (`deferred_condition::raise_condition_helper`) on it, so its condition equals the wrapper's, `kind` and `data` splicing included (#1768). Nothing Rust-owned may be live across that `Rf_eval` (it longjmps).
- `error_value.rs` — tagged-SEXP transport. `make_rust_condition_value_with_data` (5-element list: message/kind/class/call/data) is the only producer; `make_rust_condition_value` is the no-data thin wrapper used by all proc-macro codegen, and `rust_condition_value(RCondition, call)` the entry for a caught `RCondition` (primary guard, shim, `signal_now`, worker wrappers). A condition raised without a call (`ConditionCall::None`, #1725) stores `FALSE` in the call slot; the R helper reads it as `call = NULL` and `from_tagged_sexp` decodes it back, so it crosses the trait ABI. PROTECT discipline matters here (see Gotchas).
- `condition.rs` — `RCondition` enum + `error!`/`warning!`/`message!`/`condition!` macros (optional leading `call = none` (`ConditionCall`, not on `message!`), `class =` and structured `data =` payloads — Send-safe `RValue` from `rvalue.rs`, materialised on the main thread; three grammars: single pair / bracketed list / keyed `{ k = v }` sugar) + `AsRError<E: Error>`. `arg_error!(param = .., ..)` / `ArgError::raise` panic with `RCondition::Conversion` (`kind = "conversion"`, `e$param`), the generated wrapper's own argument error (#1740): its `class` slot carries the marker `CONVERSION_ERROR_CLASS_MARKER` (`".miniextendr_conversion_error_class"`), which `registry::RAISE_CONDITION_HELPER_FN` replaces with that R binding (the crate's `conversion_error_class`); raising guards replace it in Rust with `registry::conversion_error_class()` (on wasm32 from the `wasm_registry.rs` snapshot's `MX_CONVERSION_ERROR_CLASS_WASM`, #1768). `match_arg.rs` `match_arg_param` returns it with `.miniextendr_match_arg`'s exact semantics and messages (#1741): `match_arg_wording!` holds the words for both the R helper (`registry::ARG_CHECK_HELPERS`, a `concat!`) and the Rust messages, and `tests/match_arg_param.rs` compares the two input by input. `match_arg_param_with_default` does the same against a `default = "..."` parameter's formal, whose order comes from `match_arg::default_first`, the function the wrappers writer's `registry::match_arg_formal` uses too (#1767). `MatchArg::ALIASES` (#1843) is read by `match_choice` (exact choice, exact alias, prefix of a choice; `match_na` skips it) and by both R helpers' `aliases =` argument, which `registry::match_arg_aliases_arg` renders (empty without aliases) and checks with `match_arg::alias_problems`. A conversion `Err` arm words a `match_arg` choice error with the same `MatchArgError::arg_error` (`__mx_conversion_arg_message!`, passed as `conversion_condition_value`'s `arg_message`), so all three paths raise one message (#1767). The same probe takes `RConditionError::argument_message()` (`ConversionArgMessageClassed`, and a top-level `SexpError::Condition`'s `RError::argument_message`, which `From<E: RConditionError> for SexpError` carries over): a type's own whole message for every parameter of that type, `Option` / `Vec` through `check_sexp` included, never inside an `Either` (#1833); in a list of objects (`Vec` of a newtype over `List`) it is only the refused element's reason (#1837).
- `deferred_condition.rs` — `defer_warning`/`defer_message`/`defer_condition` (+ `defer_*!` macros): a process-wide `Mutex<Vec<RCondition>>` queue; the generated C wrappers call `mark()` before the body and `finish(mark, value, call)` after it, which signals everything queued in between by `Rf_eval`ing the cached `.miniextendr_raise_condition` closure (built once from `registry::RAISE_CONDITION_HELPER_FN`) inside its own `with_r_unwind_protect`, then returns the value. `with_r_unwind_protect_shim`, raising guards, guarded ALTREP callbacks and connection I/O flush too (#1518). ALTREP SEXP results are rooted across signalling; generic low-level callers must return rooted handles. R longjmps discard the abandoned queue; finalizers and connection close/destroy/Drop suppress it. No new list slots or kinds (#1448).
- `visibility.rs` — `Invisible<T>` / `Visible<T>` return markers (#1213): transparent newtypes, `IntoR` forwards to `T`; the macro peels them syntactically (last path segment) and unwraps `.0` in the call glue. Nothing is invisible by default except unit-`NULL` bare-fn returns; receiver-returning method tails are visible unless marked.
- `expression.rs` — `RCall` / `REnv` / `r_eval_str`. `RCall::eval` and `r_eval_str` catch an R error as `REvalError` (#1861): `R_ToplevelExec` (hides the caller's handlers and restarts) around `R_tryCatchError`, whose C handler stores the condition in a pre-protected slot without allocating. `REvalError` roots `list(cond, call)` with `R_PreserveObject` (released in `Drop`, so `!Send`); its `call()` drops the `doTryCatch(...)` frame call a top-level `stop()` gets. It implements `RConditionError` (message + specific classes) and `std::error::Error` (→ `RError`). `eval_with_handlers` is the other path: caller's handlers kept, R exits unwind as `RUnwind` (see Gotchas). `try_eval_with_handlers` / `RCall::try_eval_with_handlers` (#1893) combine them: `catch_error` (the `R_tryCatchError` callback `try_eval_raw` shares) runs inside `unwind_protect::call_unwinding` instead of `R_ToplevelExec`, so warnings and messages reach the caller's handlers, an error comes back as `REvalError`, and every other exit unwinds as `RUnwind`. `call_unwinding(fun, data)` is the generic `R_UnwindProtect` → `RUnwind` layer; `eval_unwinding` is its `Rf_eval` caller.
- `nargs.rs` — `NArgs` parameter marker (#1860): a `usize` newtype the generated R wrapper fills with `nargs()` (no R formal); `TryFromSexp` for the C wrapper, `IntoR` for the trait view's vtable call. Not main-thread-bound.
- `from_r.rs` — `TryFromSexp` + `r_slice` / `r_slice_mut` (handle R's 0x1 empty-vector data pointer).
- `newtype.rs` — the `Vec` / `Option` / `Vec<Option>` blankets over `TryFromSexpElement`. Where a `Vec`'s element check runs is the inner container's choice, through the hidden `TryFromSexp::__mx_try_from_sexp_with_check` (+ `_unchecked`) hook: default once on the whole input (atomic vectors), per element for `Vec<List>` / `Vec<Option<List>>` (`list.rs`, batched by `from_r::map_vecsxp_batched` / `ElementErrors`, which keep the refusals' classes); the blankets compose their own check after the one they're given (#1837). An override of one hook must override the other.
- `into_r.rs` — `IntoR` impls; `Box<[T]>` blanket + `bool`/`String` overrides.
- `coerce.rs` / `r_coerce.rs` / `strict.rs` — conversion paths; strict-mode checked variants. `r_coerce.rs` holds the `RCoerce*` S3-coercion trait family (`#[miniextendr(as = "…")]`).
- `externalptr.rs` — `Box<Box<dyn Any>>` storage, `Any::downcast` for safety, non-generic `release_any` finalizer. `prot` is `VECSXP[2 + T::R_SLOT_COUNT]`: type ID, user slot, then one value per `Sidecar<T>` field (`externalptr/sidecar.rs`, #1846, #1855). A `Sidecar<T>` holds only a pending value (`Sidecar::new`), which the three constructors, `restore_after_consuming` and every accessor flush into the field's slot through the hidden `TypedExternal::__mx_visit_sidecars` hook the derive emits (`flush_sidecars`); `into_raw` / `into_inner` load every slot back into its field as a pending value (`load_sidecars`), so a re-wrap keeps the values, and `take_for_consuming` leaves the slots in `prot`. The struct has no back-reference (#1856): the Rust accessors are associated functions taking the handle (`T::f(&ptr)` / `T::set_f(&mut ptr, v)` → `sidecar_get` / `sidecar_set`), so a plain `&self` method, a trait impl and an ALTREP callback can't reach the values (#1880). `ExternalPtr::clone` / `clone_from` flush the source and copy its slot SEXPs (`copy_sidecar_slots`), sharing the values as R objects; `mem::swap` through `DerefMut` is a plain move and the values stay with each pointer. Flush / load / the accessors / `clone` need R's main thread. An R `Sidecar` accessor (`sidecar_r_get` / `sidecar_r_set` / `sidecar_r_check`, each with a `require_live: bool` read from the `.Call()`'s last argument by `sidecar_require_live`) accepts a NULL-address pointer (after `readRDS`) when `prot[0]` is `T`'s type ID and the flag is off (the standalone `Type_get_f()`, R6 bindings, S7 properties); with the flag on (the `$` / `[[` / `$<-` / `[[<-` field methods, #1891) `checked_prot` refuses every NULL address through `refuse_restored`; a live one is checked by `Any::downcast`. A restored pointer (NULL address, `prot[0]` set) that needs its Rust value gets the classed errors of `refuse_restored::<T>` (`classify_null_address`: `Restored` → `miniextendr_restored_no_value`, `OtherVersion` → `miniextendr_restored_other_version` with `saved_version` / `current_version`, both under `miniextendr_restored`; `Foreign` / `OtherType` keep the plain messages) from `handle_downcast_failed`, `wrap_sexp_with_error` (`TypeMismatchError::{Restored, OtherVersion}` → `SexpError::Condition`), `sidecar::checked_prot` and `sidecar_r_struct[_mut]` (the derive's struct-field and computed-field accessors); the erased `from_sexp_unchecked` tolerates a NULL address (#1872). `TypedExternal::RESTORED_ERROR_CLASS` (a `&[&str]`, the package's classes put in front of the `miniextendr_restored*` ones by `restored_classes_of`) and `RESTORED_ERROR_MESSAGE` (replaces miniextendr's in both cases, `restored_message_of`) come from the derive's `#[externalptr(restored(class = ..., message = ...))]` and reach both `refuse_restored` and `TypeMismatchError` (`package_classes` / `package_message` fields; `restored_classes()` returns a `Vec`). `Computed` (`externalptr/altrep_helpers.rs`, next to `RSidecar`) is the zero-sized marker of a read-only computed field (#1883). Reading across versions is parked (#1854).
- `altrep.rs` / `altrep_impl.rs` / `altrep_bridge.rs` / `altrep_traits.rs` — ALTREP guard modes (`unsafe`/`rust_unwind`/`r_unwind`), trampolines stay on main thread.
- `panic_telemetry.rs` — RwLock-based panic hook.

## Gotchas specific to this crate
- **Every main-thread `catch_unwind` boundary must resume `RUnwind`** (#1835). `expression::eval_with_handlers` (behind `Quoted::eval`, `Quosure::eval_tidy`, `RCall::eval_with_handlers`) and `expression::try_eval_with_handlers` (errors excepted: those come back as `Err`) turn an R exit (error, `tryCatch()` exit, restart) into a Rust unwind carrying `unwind_protect::RUnwind`, with a private preserved continuation token. A site that catches panics on R's main thread must enter an `unwind_protect::Boundary` and pass the payload through `unwind_protect::resume_if_r_unwind(payload, deferred_mark, &boundary)` (or check `RUnwind::belongs_to`, `Boundary::leave`, then `RUnwind::resume`) before treating it as a panic. Otherwise `RUnwind`'s `Drop` releases the token and the user's condition is silently lost. Only the boundary that was innermost when the evaluation started may resume an exit (its jump target is an R frame of that call); any other gets `RUnwind::stray`, an error. Leave the boundary before any R jump out of it (`R_ContinueUnwind`, `Rf_error`), which skips its `Drop`. An exit dropped off the main thread queues its token; the next `call_unwinding` releases it. Sites that do it today: `run_r_unwind_protect`, ffi_guard's `CatchUnwind` mode and fallback, the worker's main-thread loop, and `run_on_worker`'s inline path. `condition::catch_condition` resumes non-`RCondition` payloads, so it passes the unwind through.
- **Tagged-condition transport is the only path** for `#[miniextendr]` fns/methods. All Rust-origin failures (panics, `Result::Err`, `Option::None`) and user conditions (`error!`/`warning!`/`message!`/`condition!`) flow through `make_rust_condition_value` → R wrapper → `stop(structure(..., class = c("rust_*", ...)))`. `Rf_error` only fires from trait-ABI vtable shims and ALTREP `RUnwind` guards. `unwrap_in_r` is semantically distinct (Result-as-value vs Result-as-error-boundary) and orthogonal to transport.
- **`with_r_unwind_protect` leaks ~8 bytes on R longjmp** (RErrorMarker + Box header). Regular panics don't leak. MXL300 warns about direct `Rf_error()` for this reason. The leak is fixed-per-unwind and non-fatal — the worker thread is fully reusable afterward (its `recv()` loop re-arms; thread-locals clear). Verified end-to-end in `rpkg/tests/testthat/test-worker-longjmp.R` (#931): 2000 longjmp-through-worker cycles do not crash and leave the worker usable, plus a `gctorture(TRUE)` interleave pass. The ~8 B/cycle leak is **not** RSS-assertable: process RSS over those cycles grows ~5–11 KB/cycle, but that's R-side garbage (condition objects, captured calls, restart frames) + allocator arenas the OS doesn't reclaim on `gc()`, swamping the real leak by ~3 orders of magnitude. The R test records the RSS delta for documentation but asserts only survival + re-usability (a hard byte ceiling flakes).
- **PROTECT discipline against R-devel GC** — `SEXP::scalar_string` and `scalar_logical(true)` allocate fresh STRSXP/LGLSXP; protect across `SET_VECTOR_ELT`/`SETATTRIB`. R-devel's GC is more aggressive — `make_rust_condition_value` crossed the threshold in PR #344 commit `af6b4875` (recursive gc + segfault at small offsets). R-release passing ≠ safe.
- **`#[macro_export]` collides with same-named modules at crate root** — `pub mod error`/`pub mod condition` shadow `error!`/`condition!` macros under `use miniextendr_api::{error, condition}` (and any `use miniextendr_api::*;` glob). Prefer the collision-free aliases `rust_error!`/`rust_condition!` (identical expansion), or invoke the bare names fully qualified. `message!` / `warning!` have no module conflict (no same-named module).
- **`R_GetCCallable` throws on miss** — does NOT return NULL. Force DLL load via `NAMESPACE importFrom(...)`.
- **`R_new_custom_connection` creates connections CLOSED with `text = TRUE`** — `RCustomConnection::build` papers over both (infers `text` from mode, invokes the `open` trampoline before returning). If you bypass the builder, you must handle both yourself or `writeBin`/`writeLines`/`seek` will fail and binary modes will reject `readBin`/`writeBin`.
- **Pointer provenance for ExternalPtr** — cache `*mut T` via `&mut T` / `downcast_mut` / `Box::into_raw`. Never write through a `*mut` derived from `&T` / `downcast_ref` — UB under Stacked Borrows.
- **Don't drop `worker-thread` on wasm** — it's tempting (R-on-wasm is single-threaded, emscripten has no usable pthreads). But `rpkg/src/rust/wasm_registry.rs` is generated by a *native* build with rpkg's default features (which include `worker-thread`); disabling it on wasm would compile out ~31 worker-gated routines and leave the snapshot with dangling entries. So the feature stays *enabled* on wasm and every spawn path in `worker.rs` is gated `all(feature = "worker-thread", not(target_family = "wasm"))` → runs inline, identical to a non-feature build (#758). This is a knock-on cost of generating the snapshot from a differently-configured build; if the snapshot ever becomes wasm-configured, revisit.

## Features
- `worker-thread`, `nonapi`, `strict`/`coerce`, `r6`/`s7` (mutually exclusive defaults), plus optional integrations (`rayon`, `serde`, `ndarray`, …). Full list in `Cargo.toml`. CI's `clippy_all` enables a curated subset; `--all-features` fails (r6-default vs s7-default).

## When changing this crate
- Add a `#[derive(…)]` or conversion impl? Update in order: `from_r.rs` → `into_r.rs` → `coerce.rs` → serde docs → rpkg fixture + testthat.
- Add a path that stores SEXPs across allocations? Add a no-arg `gc_stress_*()` fixture in `rpkg/src/rust/gc_stress_fixtures.rs` (see #430).
- `_unchecked` FFI variants (`#[r_ffi_checked]`) are valid inside ALTREP callbacks, `with_r_unwind_protect`, `with_r_thread` — MXL301 enforces.
