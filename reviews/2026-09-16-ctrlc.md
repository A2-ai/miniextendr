# Opt-in cooperative Ctrl+C

Implemented on `feat/ctrlc`, based on `0a47e633`, in the isolated `mx-ctrlc`
worktree. The user chose to retain R's SIGINT handler and use safe checkpoints.

## Implementation

The `ctrlc` feature gates the checkpoint module, registration hook, interrupt
payload, and R wrapper branch. It is excluded from defaults, aggregate features,
and scaffold auto-detection. Registration caches condition classes and initializes
R's lazy `R_tryCatch` trampoline before user Rust frames own resources. It does
not install an OS handler and adds no dependency. Wrapper-generation loads skip
initialization.

A checkpoint catches R interrupts and time-limit errors in a narrow `R_tryCatch`
call, returns from that R context, then uses typed Rust unwinding. Worker calls
poll on the R thread and unwind on their originating worker. The native boundary
returns a tagged value; the wrapper signals `rust_interrupt/interrupt/condition`
after destructors run. General R-call cleanup remains the separate #1507 problem.

## What went wrong during verification

- A minimal `ctrlc,worker-thread` rpkg build did not match the example package's
  tracked NAMESPACE and failed to load. Use its auto-detected integration set
  plus `ctrlc`. Internal feature-only fixtures carry `@noRd`, keeping default
  documentation generation stable.
- The full unoptimized macOS build exceeded the linker's compact-unwind offset
  limit. The normal release profile built without that warning.
- Initial terminal assertions assumed readiness always followed a newline. R can
  write its prompt directly before fixture output; match the complete marker's
  suffix instead. Disable readline to avoid terminal redraw noise, and wrap each
  command in braces so a failed assertion cannot reach its success marker.
- A deferred interrupt can arrive after `suspendInterrupts()` returns. Keep the
  exiting handler active through a subsequent R event checkpoint when testing
  delivery. Assert elapsed time and the Rust destructor count as well as class.
- Waiting for PTY child exit without draining terminal output stalled on macOS.
  Drain the master through EOF/EIO before `waitpid`.
- An early GC run exercised an older installed fixture after its source changed.
  Reinstall before runtime tests, and do not start a new console while an install
  is replacing that library. The final tests require the feature fixture to be
  present, rather than accepting skipped tests.

## Validation

On macOS arm64, R 4.6.1 and Rust 1.98.1:

- `just check`, `just test` (all legs, including UI), `just clippy -- -D warnings`.
- All three CI clippy configurations, using the workflow's actual feature lists.
- Feature-specific API and rpkg clippy with warnings denied; 348 API unit tests
  with `ctrlc` enabled.
- `tests/ctrlc-console.py`: actual terminal Ctrl+C for main-thread and worker
  calls, repeated cancellation, drop counts, unhandled return to the prompt,
  ordinary R interruption afterwards, and `suspendInterrupts()`; child exits 0.
- 17 targeted R assertions, including gctorture, time-limit classification, and
  direct `.Call` evidence that the native boundary returns after Rust cleanup.
- Feature-detection tests: 87 passing assertions; scaffold template sync checks.
- The original optional-dependency build was checked with defaults off, `full`,
  and explicit `ctrlc`. The final revision removes the dependency entirely.
- Formatting, project lint, and tarball lock-shape checks pass.

## Critical review for the draft PR

The original implementation retained the requested `try_set_handler` attempt.
Reviewing ctrlc 3.5.2's Unix implementation showed it temporarily installs its
handler, then restores and rejects a preexisting handler. Describing that as
leaving R's handler untouched was incorrect. The revised proposal follows the
subsequent choice to retain R's handler: it removes the dependency, registration
attempt, permanent handler thread, and atomic fallback. No runtime proof claimed
for the successful-install branch carries over; that branch no longer exists.

The console fixture now pauses for 200 ms after its readiness marker, allowing
SIGINT to become pending before the first checkpoint in a fresh R. That regression
passed before warming R_tryCatch during registration; the initialization change
also closes the source-identified first-use window where R parses its trampoline
before suspending interrupts. This is source reasoning, not a reproduced failure.

The runtime regression was initially scheduled-only. The revised workflow runs it
on Linux for PRs affecting R/runtime code or the console test and includes the job
in CI Success. Actionlint also exposed an existing interpolated reference to a
non-required macOS job inside a shell comment; removing stale commented job-result
expressions fixed it.

The local runtime evidence is macOS arm64/R 4.6.1. Linux CI is pending until the
PR runs; Windows, R GUI hosts, and webR have not been runtime-tested here. The
unhandled R condition currently prints `Error in ... : Interrupted`, although
its class does not include `error`. Checkpoint overhead has not been benchmarked;
R_tryCatch evaluates an R helper on each call, so checks belong at chunk boundaries.
These remaining validation and signalling questions are tracked in #1541,
alongside #1507's broader R-call cleanup limitation.

Final dependency-free revision: the real PTY regression and 17 R assertions passed
again after registration warm-up; feature-specific clippy passed with warnings
denied and all 348 API unit tests passed. `just force-document` completed without
tracked NAMESPACE/man changes. Workflow actionlint (without optional shellcheck)
and `git diff --check` passed.
